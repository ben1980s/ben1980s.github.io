心得

第二次參加CTF競賽想說有報名myfirstctf就順便一起報名了pre-exam,所以write up可能寫的不是很好,然後這次比較可惜的點應該就是pwn一題都沒打出來XD,看的出來第一題應該是buffer overflow 但之後就不知道要幹嘛了 這次也寫到了很多很有趣的題目也沒有太多的通靈題,也是我第一次體驗到整天坐在電腦前又解不出題目的坐牢感… 但還是覺得這次的經歷很有趣 也才讓我知道以後應該邊打CTF邊寫write-up 不然賽後再來寫有些都忘記真的要搞很久。

Hill


給了一個檔案跟一個可連接的伺服器 從裡面可以看出加密的過程

那裡面有一些比較特別的參數 像是p=251 代表所有加、減、乘運算都在模251下進行而 n = 8 代表每個「向量」／「塊」包含 8個整數

如果我們連接上了伺服器(nc chals1.ais3.org 18000)之後伺服器會根據上述的加密分式傳送出加密過後的flag

然後我們送出東西之後伺服器也會用同樣的加密手法回傳給我們加密後的訊息

從chall.py裡面其實可以看出來加密的分式其實都很線性
c = (A @ blocks[i]) % p
c = (A @ blocks[i] + B @ blocks[i-1]) % p
這兩段其實都只是簡單的矩陣相乘和相加而已
又因為加密的方式是線性化的 因此只要有足夠的樣本數就可以把flag給逆推回來

那這裡我們就寫一個腳本來解密

而腳本內部需要收集出17筆資料 而為甚麼是17筆是因為當我們送出第一筆時只有A乘上向量p0 不會涉及到矩陣B 而繼續送下一筆資料時才會變成矩陣A乘上P1+矩陣B乘上P0 後面的資料以此類推…

那矩陣內部的未知數有A跟B兩個矩陣 內部分別都有8x8格的未知數 所以總共就是128 每次發送訊息過去解密回來都只會給8個樣本 因此最終需要發送128/8 = 16筆出去 要再加上最一開始的的樣本 16 + 1 = 17 而這樣就可以湊滿需求的樣本數了

之後把第 1～16 筆混合方程拼成一個大矩陣方程 拆開A|B就可能到A、B兩張8x8陣列 之後有了A就可以求A的反矩陣還原出最一開始送的資料 後續以此類推還原後面的資料 最後再把所有的資料都串再一起就可以得到flag了

Random_RSA

給兩個檔案 chall.py跟output.txt

在chall.py裡面用了線性同餘式產生器(LCG) 找出兩個大質數p、q之後再組成RSA的n = p x q跟密文c
而在output.txt內有LCG的模數M以及三個連續使用LCG的值h0、h1、h2跟RSA中的n、e、c

LCG算法：下一個值 = (a × 現在的值 + b) mod M
而h1、h2分別是，h1 = (a × h0 + b) mod M、h2 = (a × h1 + b) mod M

有了這些條件之後就可以先找出a、b、M，之後再根據n = p x q 解出兩個質數

而p跟q的關係其實就是 從p再做k步LCG之後就會等於q 類似這樣LCG_k(p) = q
帶入剛剛n = p x q就會變成 p × LCG_k(p) ≡ n (mod M)

拿到p、q之後就把照RSA解密方式做就可以了 φ(n)=(p−1)(q−1) 再算出私鑰d做：明文 = 密文^d mod n 最後再轉換格式就可以得到flag了
